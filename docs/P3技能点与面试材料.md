## 三、STAR 简历草稿

### S：Situation

搭建一套基于 Wazuh 的 SOC 安全运营与蓝队应急响应实验环境，使用 Host-only 网络隔离攻击机、Web 靶机和 Wazuh 单节点管理平台，模拟常见攻击并验证检测、研判和处置闭环。

### T：Task

需要完成：

- Wazuh Agent、Manager、Indexer、Dashboard 部署
- Apache、DVWA、MariaDB 靶机环境部署
- 四类安全事件模拟
- 检测规则编写和调优
- 告警研判、IOC 提取和应急处置
- 编写标准化安全事件报告

### A：Action

主要工作包括：

- 配置三台虚拟机、静态 IP、Host-only 和 NAT 网络
- 在 p3-dvwa 部署 Wazuh Agent，采集 Apache、SSH、系统日志
- 配置 Syscheck 实时监控 `/var/www/html/hackable/uploads`
- 使用 Hydra、Gobuster、curl 模拟 SSH 暴破、SQL 注入和目录扫描
- 编写 Rule 100100、100200、100300，分别覆盖内容特征、频率关联和文件上下文
- 使用 UFW 对攻击源或服务端口进行最小范围临时阻断
- 使用文件隔离、SHA256、权限收紧和 HTTP 404 验证完成 FIM 事件处置
- 编写事件时间线、原始日志证据、IOC 表、影响评估和复盘建议

### R：Result

- 完成四个端到端安全事件闭环
- 实现 SSH 暴破、SQL 注入、目录扫描和 Web 文件变化的检测与响应
- 形成三条自定义 Wazuh 规则和四份安全事件报告
- 建立原始日志、告警 JSON、IOC、处置动作和验证结果的对应关系
- 将项目配置、报告和证据归档到 GitHub

## 四、面试高频题提纲

### Wazuh 架构

1. Wazuh Agent、Manager、Indexer、Dashboard 分别负责什么？
2. 日志从 Agent 到 Dashboard 的完整链路是什么？
3. Dashboard 没有数据时如何排查？
4. 1514、1515、443、9200、55000 分别是什么？

### Decoder 和 Rule

5. Predecoder、Decoder、Rule 的区别是什么？
6. `if_sid` 和 `if_matched_sid` 有什么区别？
7. `frequency`、`timeframe`、`same_source_ip` 怎么配合？
8. 为什么要使用 `wazuh-analysisd -t` 和 `wazuh-logtest`？

### 四类事件

9. SSH 暴力破解如何检测？为什么不能只看失败次数？
10. SQL 注入如何在 Apache 日志和 Wazuh 中识别？
11. 目录扫描为什么适合频率关联规则？
12. FIM 能检测哪些变化？它不能直接告诉你什么？
13. Rule 100100、100200、100300 各自的检测思路是什么？

### 应急处置

14. 告警研判的基本流程是什么？
15. True Positive 和 False Positive 怎么区分？
16. 应急处置为什么要先保全证据？
17. 为什么阻断要尽量限制到源 IP、目标服务和端口？
18. 为什么 Webshell 文件先隔离而不是直接删除？
19. 如何处理临时 UFW 规则和回滚验证？

### 报告和运营

20. 一份安全事件报告应该包含哪些内容？
21. 为什么 IOC 要标明来源？
22. 如何区分已确认影响和潜在影响？
23. 如何减少误报和告警疲劳？
24. 为什么 Dashboard 只能作为入口，最终还要回到原始日志？

## 五、需要在面试中避免的说法

不要夸大为真实企业生产环境：

- 这是自建隔离实验环境
- 没有真实业务数据
- 攻击工具仅用于自有靶机
- 发现的问题主要集中在实验靶场

可以准确表达为：

- 完成了端到端 SOC 检测和响应闭环
- 具备规则编写、日志分析、IOC 提取和应急处置能力
- 能解释 Wazuh 架构和检测流程
- 已完成文档和 GitHub 归档
